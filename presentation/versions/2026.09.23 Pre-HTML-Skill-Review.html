Slide 1 · Reference Architecture Overview

From Documents to Decisions: The sherlock Knowledge Layer

Using the complete 60-story Sherlock Holmes canon as a proving ground for enterprise unstructured documents, entity resolution, BigQuery Hybrid Search, BigQuery Graph, and BigQuery Knowledge Catalog.

1 · Understand

60 Stories → Governed Passages

  • Source: 4 novels + 56 short stories split into 60 canonical PDFs (holmes/upload/).
  • Parsing: Layout-aware chunking via AI.PARSE_DOCUMENT & Document AI into 2_book_passages.
  • Indexing: Dense vector embeddings + full-text SEARCH INDEX (idx_passage_content_search).
2 · Connect

Entity Resolution & Property Graph

  • Adjudication: Candidate pairs scored and judged in 5_er_judged_pairs (retaining rejected pairs for audit).
  • Golden Records: Unifies aliases (e.g., Sigerson, Altamont → Sherlock Holmes) in 6_characters.
  • BigQuery Graph: ISO GQL property graph sherlock.story_graph connecting Characters, Events, Locations & Stories.
3 · Serve

Hybrid GraphRAG & ADK Agent

  • Hybrid Retrieval: Reciprocal Rank Fusion over VECTOR_SEARCH + full-text SEARCH in graphrag_answer.
  • Knowledge Catalog: 12 business glossary terms linked directly to physical BigQuery columns.
  • ADK Agent: sherlock_investigator with 5 specialized tools for narrative, identity, catalog & governance audits.

Slide 2 · End-to-End BigQuery Data Lineage

Seven Governed Stages in a Single BigQuery Dataset

No external vector database or separate graph cluster required — every stage lives in all-things-knowledge-mgmt.sherlock.

Stages 0–4: Ingestion & Raw Extraction

  • 0_books_raw & 1_books_processed_docai_raw: Cloud Storage Object Table over the 60 story PDFs.
  • 2_book_passages: Chapter- and chunk-indexed text passages with full-text SEARCH INDEX.
  • 3_extracted_graph_raw: Gemini structured JSON extraction of character mentions, locations, events, and raw relationships.
  • 4_stg_*: Unresolved staging tables (4_stg_character_mentions, 4_stg_events, 4_stg_participated_in).

Stages 5–7: Entity Resolution, Graph & Hybrid Index

  • 5_er_candidate_pairs & 5_er_judged_pairs: Vector candidate blocking + LLM match adjudication (is_same_entity).
  • 6_characters, 6_locations, 6_events_resolved: Golden records + crosswalk maps (6_char_resolution_map).
  • 6_char_relationships_governed: Standardizes raw relationship verbs into Knowledge Catalog controlled categories via AI.CLASSIFY.
  • 7_passage_embeddings & 7_passage_entities: Hybrid vector + full-text index linked back to canonical entity IDs.
Walk through `sql/01_schema_and_property_graph.sql`. Highlight how keeping Stages 0 through 7 in BigQuery preserves full provenance from a resolved graph edge all the way back to the exact PDF passage.
Slide 3 · Why Hybrid Search + BigQuery Graph Matters

Closing the Proper-Noun Blind Spot in graphrag_answer

In GraphRAG, initial passage retrieval seeds the graph traversal. Pure cosine vector search misses rare proper nouns and aliases; BigQuery Hybrid Search (Vector + Full-Text RRF) guarantees exact entity recall before expanding GRAPH_TABLE.

Step 1–2: Hybrid RRF Retrieval

Combines dense semantic similarity (VECTOR_SEARCH) with sparse lexical matching (SEARCH(content, token)) using Reciprocal Rank Fusion:

rrf = 1/(60 + sem_rank) + 1/(60 + lex_rank)

Step 3: 2-Tier GRAPH_TABLE Expansion

Seeds hit_chars and hit_events from the top fused passages, then traverses sherlock.story_graph for Tier-1 passage events, Tier-2 cross-story background events, RELATED_TO edges, and resolved aliases.

Step 4: Grounded Synthesis

ML.GENERATE_TEXT synthesizes the final answer strictly from tiered graph evidence and retrieved passages, annotating every citation with both the story/chapter and retrieval mode (hybrid, semantic, or lexical).

See `sql/02_graphrag_answer_hybrid.sql` and `sql/03_agentic_era_pipeline.sql`. When a user asks about an alias like "Sigerson" or "Vandeleur", full-text search locks onto the exact token while vector search captures the narrative theme.
Slide 4 · Semantic Governance with BigQuery Knowledge Catalog

12 Business Glossary Terms Linked Directly to Physical Schema

Provisioned via createAll.sh and linked to table/column entries via attachTerms.sh, then queried live at runtime by sherlock_investigator.

Entity Resolution (5 Terms)

  • Mention → 4_stg_character_mentions.name
  • Alias → 6_characters.aliases, 6_locations.aliases
  • Canonical Entity → 6_characters.char_id, 6_locations.loc_id
  • Resolution Map → 6_char_resolution_map
  • Match Adjudication → 5_er_judged_pairs.is_same_entity

Provenance (3 Terms)

  • Source Document → 1_books_processed, 2_book_passages.passage_id
  • Narrator / Source of Record → story_metadata.narrator (Watson vs. Holmes vs. 3rd-person)
  • Record Date vs Event Date → publication_year vs. in_story_year

Graph Model (4 Terms)

  • Event → 6_events_resolved
  • Participant Role → 6_participated_in.role
  • Relationship Type → 6_char_relationships_governed
  • Location Hierarchy → 6_located_in (221B → Baker St → London)
Unlike static prompt engineering, `sherlock_agent/agent.py` includes `lookup_knowledge_catalog`, `audit_entity_resolution`, and `inspect_provenance_and_hierarchy` so the agent inspects Knowledge Catalog definitions and governance tables live.
Slide 5 · The Path to Production

Ninety days. One domain. A reusable platform.

Establish the governed knowledge layer once; compound across every subsequent business domain.

Days 0–30

Frame & Prove

  • Pick one high-value domain and agree on a 20-question golden evaluation set.
  • Ingest unstructured documents via AI.PARSE_DOCUMENT and configure autonomous embeddings.
  • Baseline naive retrieval vs. BigQuery Hybrid Search (AI.SEARCH).
Days 31–60

Connect the Brain

  • Build entity-resolution candidate blocking and adjudication (5_er_judged_pairs).
  • Define the domain property graph (CREATE PROPERTY GRAPH) in BigQuery.
  • Publish controlled vocabularies and provenance terms in BigQuery Knowledge Catalog.
Days 61–90

Serve & Scale

  • Deploy ADK agent over the Hybrid GraphRAG procedure and live Knowledge Catalog tools.
  • Enforce caller IAM / row-level security at retrieval and verify >90% groundedness on the golden set.
  • Onboard Domain #2 reusing the existing pipeline, governance model, and eval harness.
This completes the 90-day path (`Days 0–30`, `Days 31–60`, `Days 61–90`) that transitions a customer from a 2-hour discovery workshop to a reusable, governed Agentic Data Foundation.
